# 现场演示操作清单

> 打印出来，或者存到手机上。照着做就行。

---

## 一、演示前 30 分钟（**千万别省这一步**）

### 1. 跑一次「预热」

双击 **`start-demo.bat`**，等它跑完。

**为什么要预热**：首次启动要编译后端、下依赖，可能要 1-3 分钟。
预热之后依赖都缓存好了，现场启动只要 **约 25 秒**。
如果你现场才第一次跑，客户会盯着黑窗口等三分钟——很难看。

### 2. 确认页面正常

浏览器应该自动打开了 `http://127.0.0.1:8081/`。用 **`student1 / 123456`** 登录，
确认能看到：

| 项目 | 应该是 |
|---|---|
| 综合掌握度 | **25.00 分** |
| 薄弱 / 合格 / 熟练 | **2 / 0 / 0** |
| 知识点 1 | `SQL 注入` = **0.00**（已作答 1 题 · 正确率 0%） |
| 知识点 2 | `密码安全` = **50.00**（已作答 2 题 · 正确率 50%） |
| 推荐卡片 | 有，目标是 `SQL 注入` |

**看到这些就说明一切正常。** 看不到就先解决，别硬着头皮上。

> 💡 **那 25.00 分是怎么来的**：算术平均 —— (0.00 + 50.00) ÷ 2 = 25.00。
> 客户如果问「为什么是这个数」，就这么答，很干净。
>
> 之所以刻意让两个知识点分数不同（0 和 50），是为了**演示时能讲出层次**：
> 「SQL 注入一题没答对，0 分；密码安全 2 题对了 1 题，50 分」——
> 比清一色 0.00 分有说服力得多。

### 3. **把数据重置一次**

双击 **`reset-demo.bat`**，等它显示 `DONE`。

**为什么**：刚才那次预热里你可能点了东西，数据被改了。
重置后每次演示的开场数字完全一致——**这是你待会儿要讲的"25.00 分"**。

### 4. 关掉演示环境

回到 `start-demo.bat` 那个窗口，**按任意键**关闭。数据库会保持运行，不用管。

### 5. 其他准备

- [ ] 微信/腾讯会议**提前试一次**共享屏幕
- [ ] 关掉微信、QQ、邮件等**会弹通知**的软件（演示时弹窗很掉分）
- [ ] 把浏览器其他标签页关掉，只留演示页面
- [ ] 笔记本**插上电源**，别演示到一半没电
- [ ] 手机静音

## 二、开场：启动（约 25 秒）

1. **双击 `start-demo.bat`**
2. 等它自己跑完六步

你会看到：

```
[1/6] 检查运行环境
[2/6] 准备 PostgreSQL
[3/6] 启动后端（端口 8080）
[4/6] 启动网页服务（端口 8081）
[5/6] 打开浏览器
[6/6] 就绪
```

3. 浏览器自动打开，如果没打开就手动访问 **`http://127.0.0.1:8081/`**

> ⚠️ **那个黑窗口千万别关！** 它是后端和网页服务的宿主。关了演示就断了。
> 演示结束前把它最小化到任务栏就行。

## 三、演示流程（照着点，约 8 分钟）

### 第 1 幕：登录（30 秒）

浏览器上点 **`student1学生 · 有错题`** 那个按钮，再点「登 录」。

> 「这是面向校园网络安全科普的学习平台。前端是微信小程序，
> 后端 Spring Boot，数据库 PostgreSQL。为了演示我做了个网页版，
> 跟小程序共用同一套接口和数据库。」

### 第 2 幕：智能诊断 ← **重点，讲 3 分钟**

登录后直接就在这个页面。

**先指综合掌握度**：

> 「系统分析了他的作答记录，算出 6 个知识点里的掌握情况，
> 综合 **25 分**，其中 **2 个知识点低于 60 分**。」

**再讲算法**（最容易被追问，也最能加分）：

> 「掌握度不是简单的正确率，是**三个维度加权**的：
> **正确率占 50%，错误频率占 30%，最近表现占 20%**。
>
> 举两个例子说明为什么不能只看正确率：
>
> 第一，**同样 4 道题全对**，如果他从没答错过，得 100 分；
> 如果是反复错了 6 次才答对，只能得 **77.5 分**——
> 光看正确率这两个人一模一样，但明显不是一个水平。
>
> 第二，**同样 2 对 2 错**，如果最近 5 次全对得 **67.5 分**，
> 最近 5 次全错只有 **47.5 分**——这就区分出了「正在进步」和「最近退步」。
>
> 这两个数字我都写成了测试用例，跑一下脚本就能验证。」

**指知识点列表**：

> 「知识点按掌握度**从弱到强**排，最薄弱的排最前。
> 每条都有推荐理由，比如「该知识点下 1 道题全部未答对」——
> 诊断系统必须能说清**为什么是这个分数**，否则老师没法信。」

### 第 3 幕：推荐练习（1.5 分钟）

点推荐卡片上的 **「开始专项练习」**。

> 「系统自动从最薄弱的知识点里，挑出**他还没答对的题**。
> 已经会的题不会再推，避免浪费时间。」

**随便选一个选项，点「提交答案」。**

> 「答错立刻给正确答案和解析。」

### 第 4 幕：**回去看数字变了** ← 最有说服力的一下（1 分钟）

点 **「返回诊断报告」**。

> 「注意看，掌握度的数字**已经变了**。
> 每次作答后端都会**实时重算**掌握度，不是定时任务、不是假数据。
> 这是真实联动。」

> 💡 **这一下是全场最有价值的30秒。** 讲慢一点，让客户自己看到数字在变。

### 第 5 幕：其他功能（1.5 分钟，快速带过）

点顶部导航依次点一遍：

- **资讯** —— 分类筛选、搜索、点开详情（竞赛类能报名）
- **答题** —— 选作业包 → 逐题作答 → 提交得积分
- **排行榜** —— 积分排序

> 「剩下就是常规的学习平台功能：资讯、作业答题、错题本、
> 积分排行榜、活动报名、安全举报，还有一个管理端数据看板。」

### 收尾

> 「技术上：前端微信小程序原生开发，后端 Spring Boot 3.2.5 + Java 17，
> 数据库 PostgreSQL，**12 张表、57 个接口**。
> 智能化模块是**纯算法实现，不依赖任何外部大模型服务**，可以完全离线运行。」

**管理端想展示的话**：退出登录 → 用 `admin / admin123` 登录 → 「我的」页面会出现管理菜单。

## 四、客户可能问的问题

**Q：客户电脑是 SQL Server，你这是 PostgreSQL？**
> 「当前版本基于 PostgreSQL。要迁到 SQL Server 需要做一次数据库移植：
> 改建表脚本、改几处 SQL 方言、换 JDBC 驱动，大约 1-2 天。
> 主要是 `STRING_AGG`、`ON CONFLICT`、`FILTER` 这些语法两边不一样。」

**Q：小程序上架了吗？**
> 「还没。上架需要企业主体、ICP 备案和 HTTPS 域名。
> 目前是课程设计阶段，用开发者工具和网页版演示。」

**Q：智能化用大模型了吗？**
> 「没有。我用的是**可解释的加权算法**。好处是不花钱、不依赖网络、
> 结果可复现，而且**每个分数都能说清怎么来的**。
> 评审场合这一点比『调了个大模型』更有说服力。」

**Q：数据量小准不准？**
> 「有冷启动保护：作答题数少于 2 题时，错误频率和近期表现两个维度噪声太大，
> 会退化成纯正确率，并且界面上会把样本量一起显示，避免『做一题就下结论』。」

## 五、翻车预案（出问题看这里）

| 症状 | 怎么办 |
|---|---|
| **页面打不开** | 看那个黑窗口有没有报错。最常见是 8080/8081 被占用 → 关掉占用程序重跑 |
| **页面能开，但数据加载失败** | 黑窗口里找 `数据库` 相关报错。实在不行双击 `reset-demo.bat` 再重试 |
| **显示「还没有诊断数据」** | 你登错账号了，用 `student1`（他有错题记录） |
| **掌握度不是 25.00** | 之前演示改过数据 → 双击 `reset-demo.bat` 重置 |
| **黑窗口被误关了** | 重新双击 `start-demo.bat`，25 秒就好 |
| **客户要链接** | 开 cpolar/花生壳，**指向 8081 端口**，把公网地址发他 |
| **完全救不回来** | 别慌，直接说「我换个方式给你看」→ 打开 `docs/智能化模块-小程序预览版.html`（双击即可，不依赖任何服务） |

> 💡 **最后的保底方案**：`docs/智能化模块-小程序预览版.html` 双击就能在浏览器打开，
> 里面有诊断页和练习页的可交互演示。虽然数据是内置的，
> **但完全不依赖数据库和后端**，任何情况下都能展示设计。
