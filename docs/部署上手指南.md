# 部署上手指南（GitHub + 免费云平台）

> 目标：客户点一个链接就能打开系统。
>
> **先读这段，能省你半天时间：**

## ⚠️ 一个必须知道的事实

你的项目是 **微信小程序 + Java 后端 + PostgreSQL**，这不是一个纯静态网站。

| 平台 | 能不能跑 |
|---|---|
| **GitHub Pages** | ❌ 只能放静态网页。**Java 后端跑不了，数据库也没有** |
| GitHub 仓库本身 | ✅ 放代码、给别人看、留档 —— 这个可以 |
| **Railway / Render / Koyeb** | ✅ 能跑 Java + 自带 PostgreSQL，**免费用** |

所以正确做法是**两件事分开做**：

```
   你的 GitHub 仓库                      Railway / Render
┌──────────────────────┐            ┌──────────────────────┐
│  全部源代码（留档）    │            │  Spring Boot 后端     │
│                      │            │  PostgreSQL 数据库    │
│  web-demo/ ──────────┼── 发布 ──→ │                      │
│                      │            │                      │
│                      │            │  ↓ 提供 API           │
│                      │            └──────────┬───────────┘
└──────────────────────┘                       │
                                               │
                          客户浏览器 ──────────┘
                     （打开 GitHub Pages 的网址）
```

- **GitHub Pages** 放网页演示版 → 客户点这个链接看界面
- **Railway/Render** 跑后端和数据库 → 提供数据

两边一对接，客户就能用了。

# 第一部分：推到 GitHub

## 1.1 创建仓库

1. 打开 https://github.com/new
2. Repository name 填 `CyberSecurity`（或你喜欢的名字）
3. **选 Public**（Private 也能用 Pages，但免费版有限制）
4. **不要**勾选 "Add a README file"（我们本地已经有了）
5. 点 Create repository

## 1.2 本地初始化并推送

在项目根目录打开 PowerShell，逐条执行：

```powershell
cd <你的项目目录>          # 就是有 start-demo.bat 的那个目录

git init
git add .
git commit -m "网络安全科普答题平台：小程序 + Spring Boot + 智能诊断模块"

git branch -M main
git remote add origin https://github.com/<你的用户名>/CyberSecurity.git
git push -u origin main
```

> 第一次推送会弹出登录窗口，按提示授权即可。
> 如果提示要密码，用 **Personal Access Token**（GitHub 早就不支持账号密码了）：
> Settings → Developer settings → Personal access tokens → 生成一个带 `repo` 权限的。

## 1.3 确认没把不该传的传上去

项目里已经有 `.gitignore`，会自动排除：

- `backend/target/`（构建产物，58MB）
- `.idea/`、`*.iml`（IDE 配置）
- `*.log`

推完后刷新仓库页面，**应该只有源码、sql、文档**，不该有 `target` 目录。

# 第二部分：部署后端（Railway / Render / Koyeb 三选一）

三个平台都能直接读仓库里的 `backend/Dockerfile`，不用额外配置。
选一个就行，我按推荐顺序列。

## 方案 A：Render（推荐，最省心）

**免费额度**：Web Service 免费（15 分钟无访问会休眠，下次访问约 30 秒唤醒）
+ PostgreSQL 免费 90 天。

1. 打开 https://render.com/ ，用 GitHub 账号登录
2. **New → PostgreSQL**
   - Name: `cybersec-db`
   - Region: 选 `Singapore`（离国内最近）
   - Plan: **Free**
   - 创建后记下它给的 **Internal Database URL**（形如 `postgres://user:pass@host/db`）
3. **New → Web Service**
   - 连接你刚推的 GitHub 仓库
   - **Root Directory** 填 `backend` ← **很重要，别漏**
   - Runtime: **Docker**（它会自动找到 `backend/Dockerfile`）
   - Region: 同样选 `Singapore`
   - Plan: **Free**
4. 在 **Environment Variables** 里加三条：

   | Key | Value |
   |---|---|
   | `SPRING_DATASOURCE_URL` | `jdbc:postgresql://<host>:5432/<database>` |
   | `SPRING_DATASOURCE_USERNAME` | 数据库页面上给的用户名 |
   | `SPRING_DATASOURCE_PASSWORD` | 数据库页面上给的密码 |

   > ⚠️ **注意格式差别**：Render 给你的是 `postgres://...`，
   > 但 Spring 要的是 `jdbc:postgresql://...`。
   > 把 `postgres://` 换成 `jdbc:postgresql://` 就行，其余照抄 host 和库名。
   > 这一步最容易错，填错了后端会启动失败。

   再加一条关掉 SQL 日志：

   | Key | Value |
   |---|---|
   | `SQL_LOG` | `none` |

5. 点 Create。等它构建（首次约 5-10 分钟，要下 Maven 依赖）
6. 构建完成后，右上角会给你一个网址，形如：
   `https://cybersec-backend-xxxx.onrender.com`
   **记下它**，第三部分要用。

## 方案 B：Railway

1. https://railway.app/ ，GitHub 登录
2. **New Project → Deploy from GitHub repo** → 选你的仓库
3. 建好后进 Service → Settings → **Root Directory** 填 `backend`
4. **New → Database → Add PostgreSQL**
5. 进后端服务的 Variables，点 **"Add Reference"** 引用数据库变量，
   或者手动填（同样注意 `jdbc:postgresql://` 前缀）
6. **New → Generate Domain** 拿到公网地址

> Railway 现在没有永久免费额度（新账号送 $5 试用），
> 长期跑要绑卡。演示用途够用，长期建议 Render。

## 方案 C：Koyeb

免费额度给得比较实在（1 个 Web Service + 1 个 PostgreSQL，无需绑卡）。
流程和 Render 类似：Create Service → GitHub → 选仓库 → 构建方式选 Dockerfile →
工作目录 `backend` → 配环境变量 → 加一个 PostgreSQL 数据库。

# 第三部分：把表结构和演示数据导进去

后端跑起来了，但数据库是空的。需要执行两个 SQL 文件。

**在 Render/Railway 的后台找到数据库的「连接信息」**（host / port / user / password），
然后在你本地执行（本地要有 psql，`start-demo.bat` 已经帮你装好了）：

```powershell
# 用 psql 连到云端数据库
$env:PGPASSWORD="云端数据库密码"

# 建表
psql -h <云端host> -p 5432 -U <云端用户名> -d <云端库名> -f db/schema.sql

# 灌演示数据
psql -h <云端host> -p 5432 -U <云端用户名> -d <云端库名> -f db/seed.sql
```

> Render 的免费 PostgreSQL 可能只允许**内部连接**（同区域内网）。
> 如果连不上，用 Render 后台自带的 **PSQL Command** 网页终端执行：
> 把 `db/schema.sql` 和 `db/seed.sql` 的内容复制进去粘贴执行。

**验证**：浏览器打开

```
https://你的后端地址/api/news/list
```

应该返回一坨 JSON（里面有中文资讯）。**看到 JSON 就说明后端 + 数据库都好了。**

# 第四部分：发布网页演示版到 GitHub Pages

## 4.1 配置仓库变量

1. 仓库页面 → **Settings → Secrets and variables → Actions**
2. 切到 **Variables** 标签 → **New repository variable**
3. 填：

   | Name | Value |
   |---|---|
   | `API_BASE_URL` | `https://你的后端地址`（**末尾不要带 /**） |

## 4.2 开启 Pages

仓库 → **Settings → Pages** → Source 选 **GitHub Actions**

## 4.3 触发发布

推一次代码，或者在 **Actions** 页面点 `Deploy web demo to GitHub Pages` → **Run workflow**。

等一两分钟，发布完成后你会拿到：

```
https://<你的用户名>.github.io/<仓库名>/
```

**这个就是给客户的链接。**

## 如果打不开，按这个顺序排查

| 现象 | 原因 | 怎么查 |
|---|---|---|
| 页面能开，但一直提示"无法连接后端" | `API_BASE_URL` 没填或填错 | 打开 `https://你的用户名.github.io/仓库名/js/config.js`，看 `BASE_URL` 是不是你的后端地址 |
| 同上 | 后端没起来 / 已休眠 | 直接访问 `https://后端地址/api/news/list` 看有没有 JSON。免费版休眠的话等 30 秒再试 |
| 后端地址返回 500 | 数据库环境变量填错了 | Render 后台看 Logs，找 `Connection refused` 或 `password authentication failed` |
| 登录提示"用户名或密码错误" | 没执行 `seed.sql` | 回第三部分补上 |
| 浏览器控制台报 CORS 错误 | 一般不会，后端已放开跨域 | 后端 `WebMvcConfig` 里配了 `allowedOriginPatterns("*")`，理论上不会；若有，看后端日志 |

> 💡 **关于端口**：后端读的是环境变量 `SERVER_PORT`（默认 8080）。
> 大多数平台的 Docker 部署不用管它，容器内监听 8080 即可。
> 如果平台强制要求监听它注入的 `PORT`，在后端服务的环境变量里加一条
> `SERVER_PORT` = 平台给的端口值就行。
>
> （这里刻意没有直接用 `PORT`：实测本机环境里恰好也有个 `PORT`，
> 后端会去抢那个端口导致启动失败。`SERVER_PORT` 名字更具体，不会被误撞。）

> 💡 **免费版的休眠问题**：Render 免费服务 15 分钟没人访问就休眠，
> 客户第一次打开要等 30 秒左右。
> **演示前 5 分钟自己先访问一次**把它唤醒，客户就感觉不到延迟了。

# 附：每一步在做什么（给答辩用）

如果老师问"你怎么部署的"，可以这么答：

> 「代码托管在 GitHub，配了 CI 每次推送自动跑四个自检：后端编译、
> 数据库结构一致性、小程序静态检查、算法不变式验证。
>
> 后端用 Docker 多阶段构建打包成镜像，部署在 Railway/Render 上，
> 数据库用平台提供的 PostgreSQL。
>
> 前端用 GitHub Actions 自动发布到 GitHub Pages。
> 因为是前后端分离，跨域问题在后端用 CORS 配置解决，
> 前端通过运行时配置注入后端地址，同一份代码既能本地跑也能部署到云端。」

# 附：本地还能用吗？

**能，而且不受影响。** 部署用的配置全部走环境变量，
本地不设这些变量时用的还是默认值（`localhost:5432`）。

`start-demo.bat` 照常双击就能用。

Docker 那套是给「有 Docker 的机器 / 自己的服务器」用的额外选项，
你不用也不影响。
