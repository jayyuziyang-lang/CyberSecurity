# 远程演示操作手册

> 场景：客户在**异地**，你在自己电脑上演示，客户**什么都不用装**。
> 你需要的：一台装了 PostgreSQL 的 Windows 电脑 + 网络。

---

## 〇、先搞清楚一件事（30 秒读完）

**别在客户电脑上跑任何东西。** 让客户"打开一个网址"是最不容易翻车的做法，
因为浏览器没有微信小程序那些限制（不需要 HTTPS、不需要备案、不需要证书）。

所以整条链路是：

```
你的电脑                          客户
┌─────────────────────┐
│ PostgreSQL  ← 数据   │
│ 后端 :8080           │
│ 网页 :8081           │  ←──── 客户浏览器打开链接
└─────────────────────┘
```

**你演示时开的窗口**：一个网页（就是上面那个 :8081）。

---

## 一、演示前一天：把环境跑通

### 1.1 装 PostgreSQL（只需一次）

如果你电脑还没装：

1. 打开 https://www.postgresql.org/download/windows/
2. 下载安装包，一路下一步
3. **安装时设的密码记牢**，默认超级用户是 `postgres`
4. 端口保持默认 `5432`

> ⚠️ 装完不需要建库，下面的脚本会引导你。

### 1.2 改数据库密码

打开 `backend/src/main/resources/application.yml`，把这一行改成你自己的密码：

```yaml
  datasource:
    password: 123456      # ← 改成你安装时设的密码
```

### 1.3 建库 + 灌演示数据

打开 PowerShell，进到项目根目录，依次执行：

```powershell
createdb -U postgres cybersec_db

psql -U postgres -d cybersec_db -f db/schema.sql
psql -U postgres -d cybersec_db -f db/seed.sql
```

提示输入密码就输入你刚设的密码。

**验证一下**（应该列出 12 张表）：

```powershell
psql -U postgres -d cybersec_db -c "\dt"
```

### 1.4 一键启动，自己先走一遍

在项目根目录双击/执行：

```powershell
powershell -ExecutionPolicy Bypass -File start-demo.ps1
```

它会自动：检查环境 → 启动后端 → 启动网页 → 打开浏览器。

浏览器里用 **`student1` / `123456`** 登录，确认能看到「智能诊断」页面上有数据。

> 首次启动要下载 Maven 依赖，可能等 1–3 分钟，属于正常。
> 之后再启动大约 20 秒。

**跑通了就关掉窗口**（按任意键），准备正式演示。

## 二、演示当天：两种方式，选一种

### 方式 A：共享屏幕（**推荐，最稳**）

适合：腾讯会议 / 微信视频 / 钉钉 等任何能共享屏幕的场合。

**操作：**

1. 启动 `start-demo.ps1`，等浏览器自动打开
2. 发起视频通话，**共享你的屏幕**（不是摄像头，选「共享屏幕」→ 选那个浏览器窗口）
3. 客户看你的操作，你边讲边点

**为什么推荐**：没有任何网络穿透、没有域名、没有证书，也不会因为客户网络问题卡住。
出问题你能自己马上处理，客户只是"看电视"。

### 方式 B：给客户一个链接（客户自己点）

适合：客户想自己动手点点看，或者你想显得"这是个真能访问的系统"。

需要一个**内网穿透**工具，把本机的 `8081` 端口暴露到公网。

**步骤：**

1. 先启动 `start-demo.ps1`（后端 8080 + 网页 8081 都跑起来）
2. 启动穿透工具，**把穿透目标指向本机 `8081`**
3. 拿到工具给你的公网地址，例如 `https://xxxx.cpolar.cn`
4. 把链接发给客户：**让他直接打开这个地址即可**

**穿透工具选择：**

| 工具 | 免费额度 | 说明 |
|---|---|---|
| **cpolar** | 有免费隧道 | 国内可用，免费版地址每次会变 |
| **花生壳** | 有免费版 | 老牌，需注册 |
| **ngrok** | 有免费版 | 国外，国内访问可能偏慢 |
| **natapp** | 有免费隧道 | 国内可用 |

> ✅ **只需要穿透 8081 一个端口就够了。**
> `web-demo/serve_demo.py` 会把 `/api/**` 反向代理到本机 8080，
> 所以客户打开 `https://xxx.cpolar.cn` 时，页面和接口走的是同一个域名，
> 你不需要分别暴露两个端口，也不会遇到跨域问题。
>
> ⚠️ 别用 `python -m http.server` 手动起服务——它不会代理 `/api`，
> 客户打开会看到一片空白或 501 报错。`start-demo.ps1` 已经帮你用对了脚本。

## 三、演示脚本（照着念就行，约 8 分钟）

### 第 1 幕：登录（30 秒）

> "这是一个面向校园网络安全科普的学习平台，前端是微信小程序，后端是 Spring Boot。
> 为了今天演示我做了个网页版，跟小程序共用同一套接口和数据库。"

点演示账号按钮填入 `student1`，登录。

### 第 2 幕：智能诊断 —— **重点，讲 3 分钟**

> "登录后直接进的是**学习诊断报告**。这是项目的智能化模块。"

指着综合掌握度：

> "系统根据这个学生的作答记录，算出了他在 6 个知识点上的掌握度，
> 平均分是 XX 分，其中 3 个知识点低于 60 分。"

**然后讲算法**（这是最容易被追问、也最能加分的地方）：

> "掌握度不是一个简单的正确率，而是三个维度加权的：
> **正确率占 50%，错误频率占 30%，最近表现占 20%**。
>
> 为什么要三个维度？我举两个例子：
>
> 第一，**同样 4 道题全对**，如果他是从来没答错过，得 100 分；
> 但如果是反复错了 6 次才答对，只能得 77.5 分。
> —— 光看正确率这两个人是一样的，但明显不是同一个水平。
>
> 第二，**同样 2 对 2 错**，如果最近 5 次全对，得 67.5 分；
> 如果最近 5 次全错，只有 47.5 分。
> —— 这就区分出了'正在进步'和'最近退步'的学生。
>
> 这两个数字我都写成了测试用例，跑 `node tools/verify_mastery_algorithm.js` 就能验证。"

指着知识点列表：

> "知识点按掌握度**从弱到强**排，最薄弱的排最前面。
> 每一条都有推荐理由，比如'该知识点下 3 道题全部未答对'——
> 诊断系统必须能说清'为什么是这个分数'，否则老师没法信。"

### 第 3 幕：个性化推荐练习（1.5 分钟）

点最薄弱知识点上的「开始专项练习」：

> "系统自动从最薄弱的知识点里挑出**他还没答对的题**。
> 注意：已经答对的题不会再推给他，避免浪费时间。"

答一题（故意答错）：

> "答错会立刻给正确答案和解析，同时这条记录会写进错题本。"

### 第 4 幕：**回去看数字变了** —— 这是最有说服力的一下（1 分钟）

点「返回诊断报告」：

> "注意看，掌握度的数字已经变了。
> 每次作答后端都会实时重算掌握度，不是定时任务、不是假数据。
> 这是真实联动。"

### 第 5 幕：其他功能（1.5 分钟，快速带过）

- **资讯**：点分类筛选、搜索、打开详情
- **答题**：作业包 → 逐题作答 → 提交得积分
- **排行榜**：积分排序

> "剩下的就是常规的学习平台功能：资讯发布、作业包答题、错题本、积分排行榜、
> 活动报名、安全举报，以及一个管理端的数据看板。"

### 收尾

> "技术上，前端是微信小程序原生开发，后端 Spring Boot 3.2.5 + Java 17，
> 数据库 PostgreSQL，一共 12 张表、57 个接口。
> 智能化模块是纯算法实现，不依赖任何外部大模型服务，可以完全离线运行。"

## 四、可能被问到的问题（提前准备）

**Q：为什么客户电脑是 SQL Server，你用的是 PostgreSQL？**
> "当前版本是基于 PostgreSQL 开发的。如果要用 SQL Server，
> 需要做一次数据库移植：改建表脚本、改几处 SQL 方言、换 JDBC 驱动，大约 1–2 天。
> 主要是 `STRING_AGG`、`ON CONFLICT`、`FILTER` 这些语法两边不一样。"

**Q：这个小程序上架了吗？**
> "还没有。上架需要企业主体、ICP 备案和 HTTPS 域名。
> 目前是课程设计阶段，用开发者工具和网页版演示。"

**Q：智能化用了 AI 大模型吗？**
> "没有。我用的是可解释的加权算法，好处是：不花钱、不依赖网络、
> 结果可复现，而且**每个分数都能解释清楚是怎么来的**。
> 答辩和评审场合这一点比'调了个大模型'更有说服力。"

**Q：数据量小了准不准？**
> "有冷启动保护：作答题数少于 2 题时，错误频率和近期表现两个维度噪声太大，
> 会退化成纯正确率，并且界面上会把样本量一起显示出来，
> 避免'做一道题就下结论'。"

## 五、翻车预案

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 页面打开一片空白 | 网页服务没起来 | 看 `start-demo.ps1` 有没有报错；确认 8081 端口没被占 |
| 页面能开但数据加载失败 | 后端没起来 / 数据库没连上 | 看那个最小化的命令行窗口里的报错；多半是 `application.yml` 里密码不对 |
| 提示「没有诊断数据」 | 登录的账号没有作答记录 | 换 `student1`（种子数据里给他造了错题） |
| 首次启动等很久 | 在下载 Maven 依赖 | 正常，1–3 分钟；**演示前一定要先跑一次预热** |
| 客户打不开穿透链接 | 穿透工具断了 / 地址过期 | 免费版地址会变，重新拿一次；或者切回共享屏幕 |
| 端口 8080 被占用 | 上次没关干净 | 脚本会自动跳过并复用；实在不行重启电脑 |

**最重要的一条：演示前一天一定要完整跑一遍。** 首次启动要下依赖，
当场第一次跑大概率会卡在等待上，很难看。

---

## 六、一句话总结

> **共享屏幕演示网页版**，客户零安装、零配置；
> 想给链接就加个内网穿透指向 **8081**（一个端口就够，`/api` 已由代理转发）。
> 别让客户碰他的电脑，也别指望微信小程序能"发个链接就看"。
