## 0. 最重要的结论（三句话）

1. **这个项目已经是一个微信小程序了** —— `app.json` + `.wxml/.wxss/.js` + `tabBar` + `wx.request` 是标准原生小程序结构，AppID `wxcbae1cf5d036eb2d`，19 个页面。所以"想做成一个小程序"不是**重写**，而是**加固 + 真实对接 + 上线**。
2. **但它现在处于"答辩演示版"状态，跑不起来也过不了审**：当前仓库**编译失败**（2 个文件带 UTF-8 BOM）；登录**没有调用微信**；后端鉴权实际上是**关闭**的；实名认证在前端是**写死的假流程**。
3. **真正的工作量不在写代码，而在三件事的决定**：主体资质（个人 / 企业）、域名 + ICP 备案 + HTTPS、以及"实名认证"这个功能要不要保留。

## 2. 已做的真实验证（不是猜的）

### 2.1 编译验证 ⚠️ 结论：当前仓库编译不通过

我实际用 `Maven 3.9.9 + JDK 17` 跑了 `mvn -DskipTests compile`：

```
[ERROR] AuthController.java:[1,1] 非法字符: '\ufeff'
[ERROR] AuthController.java:[1,10] 需要 class、interface、enum 或 record
[ERROR] ReportServiceImpl.java:[1,1] 非法字符: '\ufeff'
[ERROR] ReportServiceImpl.java:[1,10] 需要 class、interface、enum 或 record
[INFO] 4 errors
[ERROR] BUILD FAILURE
```

字节级确认：

| 文件 | 首 3 字节 | 结论 |
|---|---|---|
| `controller/AuthController.java` | `EF BB BF` | **带 UTF-8 BOM，编译失败** |
| `service/impl/ReportServiceImpl.java` | `EF BB BF` | **带 UTF-8 BOM，编译失败** |
| `controller/QuizController.java` | `70 61 63` | 正常 |
| `entity/User.java` | `70 61 63` | 正常 |

**在临时副本中剥掉这两个 BOM 后，75 个源文件全部编译成功（BUILD SUCCESS）。**

> 也就是说：**只需删掉 2 个不可见字符，后端代码立刻能编译。** 这是全项目性价比最高的一个修复。
>
> 附带说明：`target/classes/` 里有编译产物，但那是**别的机器、别的路径**下构建的（`target/maven-status/.../inputFiles.lst` 指向 `D:\Javasoft\IdeaProjects\wechat-cybersec-platform\`），不能证明当前源码可编译 —— 实测已经证明它不可编译。

### 2.3 数据库真实性反解

`.idea/dataSources/` 里存着一份 IDE 同步下来的**真实库结构快照**，只有：

```
表 user（唯一一张）: id, openid, nickname, avatar_url, role(varchar(32)), create_time
```

而**代码需要 9 张表**：`user / news / quiz / quiz_paper / quiz_bank / wrong_set / report / registration / real_name_auth`。

同时 `db/` 目录里**只有 2 个 SQL 文件，且全是 `ALTER` 语句**：

```sql
ALTER TABLE "user" ADD COLUMN IF NOT EXISTS is_authenticated ...   -- 改一个不存在的表
ALTER TABLE news  ADD COLUMN IF NOT EXISTS is_competition ...      -- 改一个不存在的表
```

**结论：建表 DDL 根本不在仓库里。** 任何人拿到这个 zip 都无法建库、无法启动系统。这是一个"能跑只因为作者本地那台机器上有库"的项目。

## 3. 问题清单（按"能不能上线"排序）

### 🔴 P0 — 阻断级：不做就无法上线

| # | 问题 | 位置 | 后果 |
|---|---|---|---|
| 1 | **2 个文件带 BOM，编译失败** | `AuthController.java`、`ReportServiceImpl.java` | 全新环境 100% 构建失败 |
| 2 | **建表 DDL 缺失 5 张表** | `db/` 只有 ALTER | 换台机器就起不来；无法交付 |
| 3 | **登录完全没接微信** | 前端 `login.js` 账号密码；后端无 `jscode2session` | 小程序审核重点项，且用户要重填账号 |
| 4 | **鉴权实际是关的**（见下） | `LoginInterceptor.java:32-46` | 任何人可冒充任何用户 / 进管理端 |
| 5 | **所有接口写死 `127.0.0.1`** | 全部页面的 `wx.request` | 真机必然失败 |

### 🔴 P0 详解：鉴权为什么等于没有

`LoginInterceptor.preHandle()` 在**每一条失败路径上都 `return true`（放行）**：

```java
String userIdText = request.getHeader("X-User-Id");
if (!StringUtils.hasText(userIdText))   return true;   // 没带 header → 放行
if (NumberFormatException)              return true;   // 格式错 → 放行
if (user == null)                       return true;   // 用户不存在 → 放行
// 只有 role==0 且未实名 才拦截
```

后果（都是可直接复现的）：

- 请求头写 `X-User-Id: 1` → **你就是 1 号用户**，密码不需要。
- 完全不带头 → 放行，所以 **`/api/admin/**` 全部匿名可调**：发布公告、增删题目、审核举报，都不需要登录。前端 `userRole !== 1` 的检查只是客户端 UI 判断，绕过成本为零。
- `POST /api/quiz/submit` 只传 `{userId}` 就 **+20 分**，不校验答案、不校验是否已提交 → **无限刷分**（前端 `quiz.js:142` 走的正是这条路）。
- `POST /api/user/login` 返回的 `token` 是随机 UUID，**后端从不存储、从不校验**，前端只把它当"已登录"的布尔开关用。

## 4. 关键判断："做成小程序"到底还剩什么

因为**前端已经就是小程序**，所以"做成小程序"的真实含义 = **让它在微信里真正跑起来并通过审核**。拆成 4 条独立战线：

### 战线 A：技术加固（可并行，纯代码）

- 删 BOM → 编译通过
- 补 9 张表的完整 DDL + 种子数据（**这是交付的必需品**）
- 后端接管微信登录（`wx.login` → `code` → `jscode2session` → `openid` → 自建 JWT）
- 修复鉴权：拦截器改为"未登录一律 401"，`/api/admin/**` 强制 `role=1`
- 密码 BCrypt；身份证加密存储；积分改为服务端判卷
- `baseUrl` 抽成配置（开发 `127.0.0.1` / 生产 `https://api.xxx.com`）

### 战线 B：微信平台资质（**决定功能上限，必须先定**）

| 事项 | 说明 |
|---|---|
| 小程序主体 | **个人 vs 企业**，直接决定能开哪些类目和权限 |
| **ICP 备案** | 2023 年 9 月起小程序需完成备案才能上架（工信部要求） |
| 服务器域名 | 必须 **HTTPS + 已备案域名**，在"开发设置→服务器域名"里配置；`127.0.0.1` 仅开发者工具能通 |
| 类目选择 | 教育/培训类目通常需要资质；需按主体能力选 |
| 实名认证 | **个人主体基本拿不到实名认证接口**，人脸核身门槛更高 → 见下方决策点 |

### 战线 C：部署基础设施

- 一台**有公网 IP 的国内服务器**（阿里云/腾讯云轻量）
- **已备案域名** + **SSL 证书**（备案通常 7–20 个工作日，**这是最长的一条关键路径**）
- PostgreSQL + 后端 jar 用 systemd/Docker 常驻
- 微信后台配置 `request 合法域名`

### 战线 D：留痕与演示（如果近期要交作业/答辩）

在 A/B/C 完成前，可以先用"**开发者工具 + 真机调试（打开不校验合法域名）**"跑通演示，但**这条路线上面的鉴权漏洞和假实名必须至少修掉**，否则演示时被问到会很难看。

## 5. 必须先做的 3 个决策

### 决策 1：主体用个人还是企业？

| | 个人主体 | 企业主体 |
|---|---|---|
| 注册成本 | 免费（2023 年起小程序认证免费） | 需营业执照 + 对公验证 |
| 可用类目 | 受限，教育类多不可选 | 基本都可用 |
| 实名认证接口 | ❌ 基本不可用 | 可申请（仍需资质） |
| 支付 | ❌ | ✅ |
| 适合 | 校园科普演示、竞赛作品 | 真实学校/机构运营 |

> **如果这个项目是课程作业/竞赛作品 → 个人主体 + 砍掉真实名认证，是唯一现实路径。**
> 如果是学校要正式运营 → 必须走企业主体（学校法人）。

### 决策 2：实名认证保留吗？

现状是"假实名"，有三个选项：

- **A. 砍掉**（推荐给演示场景）：移除 `auth/verify` 页面和 `is_authenticated` 门禁，用微信 `openid` 作为唯一身份。**成本最低、最干净、没有合规风险。**
- **B. 降级为"信息登记"**：改叫"填写姓名学号"，明确不叫实名认证，且**不存储身份证号**。
- **C. 真接三方核验**：需要企业主体 + 三方 API 费用（约 1–3 元/次）+ 合规评估。**不建议学生项目做。**

> ⚠️ 无论选哪个，**当前"明文存身份证号 + 前端假认证"的组合都是必须立刻改掉的**，它的性质是"伪造安全功能"，比没有这个功能更糟。

### 决策 3：登录方式

强烈建议**改成微信一键登录**（`wx.login` + `button open-type="chooseAvatar"` + `type="nickname"`）：

- 用户体验：不用注册、不用记密码
- 审核友好：微信登录是小程序标准范式
- 安全上界：`openid` 无法被伪造，而自建账号密码方案里**密码是明文存的**
- 同时可以删掉整个 `login` 注册页 → 少一个页面、少一堆漏洞

### A.2 一个「修出来的新 bug」及其纠正（值得记录）

补 DDL 时我给 `real_name_auth.user_id` 加了唯一索引，注释写着"兜底去重"。但
`AuthController.verify` 是**每次调用都无条件 INSERT**（无去重、无 upsert）：

- 加唯一索引 → 学生**第二次**点实名认证就触发 `SQLSTATE 23505` → **HTTP 500**
- 索引并不能修复幂等性缺陷，**反而制造了一个 500**

已改为普通索引，并按"追加日志"语义使用该表。这个案例说明：
**"加约束让它更安全"这种直觉，必须先核对写入路径是否满足该约束。**
